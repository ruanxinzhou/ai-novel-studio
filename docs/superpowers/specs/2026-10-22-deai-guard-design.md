# spec 2 · 去 AI 味护栏（保守方案）

- 日期：2026-10-22
- 状态：已批准，待实施
- 前置：spec 1（事件溯源账本）已落地，本spec 复用其 `before`/`guard` 字段
- 范围：只做检测 + 回滚，**不修改任何现有替换规则**

## 背景

`postprocess()` 是无条件全量替换链，跑完直接覆盖原文（`engine.py:501`），没有 diff、没有校验、没有回滚。

实测破坏性（`postprocess` 前后 `difflib` 比对）：

| 输入 | 删除比例 | 输出 |
|---|---|---|
| `空气仿佛凝固了。` | **100%** | 整句消失 |
| `他感到恐惧涌上心头。` | 53.8% | `他感到`（残句） |
| `他眼中闪过一丝复杂的情绪。` | 30.0% | `他复杂的情绪`（语法崩） |
| `与此同时，他推开了门。` | 29.4% | `他推开了门。`（合理） |

**信息守恒是破的**：`眼中闪过一丝` 被规则删掉后，`一丝 → 一点` 这条规则又把剩下的部分改成「他眼中闪过一点笑意」——原句里根本没有「一点」。这是多规则接力产生的凭空注入。

## 一、三条护栏

核心原则：**护栏只做否决权，不做修改权**。三条全部是「检测到崩坏 → 退回原文」，不存在「修复」动作。最坏情况是这次去味没生效，而不是把正文改坏。

### 护栏 1 · 残句检测

不做真正的中文语法分析，用轻量特征：

| 特征 | 判定 |
|---|---|
| 悬空心理动词 | `感到/觉得/意识到` 后无宾语（到句末或标点为止） |
| 空谓语残留 | 3 字以内且以 `感到/觉得/意识到` 结尾 |
| 比例突降 | 单章删除比例 > 60% |

### 护栏 2 · 新增实词检测（信息守恒硬指标）

```
new = content_words(after) - content_words(before)
```

原始判据来自 skill 的「禁注入护栏」：改写后的每个实词能否在原文指出出处？指不出就撤销。

**关键区分**：合法替换也会产生新实词（`仿佛 → 好像`、`一丝 → 一点`）。这些是 `_SAFE_REPLACES` 里作者自己写的，不能判违规。

所以判据精确到只抓**意外**：新增实词若不在 `_SAFE_REPLACES` 的替换目标词白名单内，即为意外 → 回滚。

> 这是本护栏最容易写错的地方。做粗了会把 60 多条合法规则全判成违规（测试项 6 专门验这条）。

### 护栏 3 · 段落级守恒

逐段对比，删掉超过 50% 内容的段落回滚。防止整章被逐步蚕食——单段看每处都「合理」，合起来可能删掉三分之一。

## 二、落库与可见性

护栏结果写进 spec 1 账本的 `guard` 字段：

```json
"guard": {"rolled_back": true, "reason": "新增实词:一点",
          "added_words": ["一点"], "delete_ratio": 0.53}
```

同时发一条 SSE `notice`，让作者在写作台看得见「本次后处理被回滚，正文保留原稿」。

**静默回滚会让人以为规则生效了，其实没有** —— 可见性是这条护栏的必要组成部分，不是附加项。

## 三、明确不做的三件事

**不碰破折号规则。** 实测 `_replace_dashes` 会把作者的插入语转逗号，但 `engine.py` 注释明确写了「按用途管不按密度管，跨模型差异 40 倍」，这是有意取舍。护栏不介入。

**不尝试修复残句。** 修复需要中文语法判断，误伤风险高于收益。

**不改任何 `_SAFE_REPLACES` 规则。** 这批规则是长期积累出来的，有些看起来激进（比如删整个「空气仿佛凝固了」）但在 AI 味正文里是对的。删规则是独立判断，需真实语料支撑。

**不改文风卡优先级裁决。** `style_dna.md:28` 已经写了「文风卡 > 通用规则：蒸馏产物记录的是目标作者的真实写法，不属生成痕迹」。本护栏与之一致——不把作者风格当AI 痕迹处理。

## 四、测试策略

| # | 测试 | 样本 | 期望 |
|---|---|---|---|
| 1 | 残句回滚 | `他感到恐惧涌上心头。` | 回滚 + 报P1 |
| 2 | 整句消失回滚 | `空气仿佛凝固了。` | 回滚 |
| 3 | 凭空注入回滚 | `眼中闪过一丝笑意` | 回滚，added=`一点` |
| 4 | 合法替换放行 | 触发 `仿佛→好像` | **放行**（白名单内） |
| 5 | 段落守恒 | 删超 50% 的段落 | 回滚 |
| 6 | **合法规则不误杀** | 遍历全部 `_SAFE_REPLACES` | 无意外回滚 |
| 7 | 正常正文零干预 | 500 字自然散文 | 无回滚、无 P1 |
| 8 | 账本留痕 | 触发回滚 | `guard` 字段完整 |
| 9 | 回归基线 | 全量测试 | 39 failed / 394 passed |

第 6 项是护栏正确性的关键：护栏最大的风险不是漏检，而是把现有合法规则全判成违规。

## 五、附带修复

`style_dna.md:44` 残留一条「章末切场只能切到他**梦里**的画面」，与 spec 1 轮修掉的 `prompts.py` 错误同源。该文件通过 `_load_style_dna()` 注入 prompt，会把错误重新注入。已在本 spec 一并修复。

## 六、不做什么

- 不做「检测+尝试修复」的积极方案（已评估，误伤风险高于收益）
- 不做模型级复核（成本高，且规则层拦住已足够）
- 不改 `_SAFE_REPLACES` 任何条目
- 不做跨章的护栏效果统计（留待spec 3 用账本数据回溯分析）
