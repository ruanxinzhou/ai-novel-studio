# spec 1 · 事件溯源账本 + 质量闭环回流

- 日期：2026-10-22
- 状态：已批准，待实施
- 范围：`novel-studio` 后端，纯增量，不改任何现有阈值

## 背景

逆向分析 novel-studio、super-writer-bor、writing-universe 三方后确认的核心缺口：

现在的门禁只能拦住**单章写坏**，拦不住**一本书在退化**。第 1 章问号密度 8/千字、第 20 章降到 2/千字——每章单独看都过 P0 线（阈值 2.0），整本书已经变成说明书。

`hard_gate` 看不见这件事，因为它的 stats 算完只发一次 SSE 就销毁（`engine.py:542`）。落盘的只有 `entities.json`（设定事实）与 `lexicon.json`（描写重复），**质量指标一条都没存**。

更关键的是：即使存了，也只是「记录」，不是「闭环」。真正的闭环是**检测结论自动变成下一章的生成约束**——让退化在发生前被拦住，而不是发生后被记录。

本 spec 是四步改进计划的第一步。四步（事件溯源账本 / 去AI 味护栏 / 一致性引擎 / 人工确认门）共用一根轴：一本账，四个字段。本 spec 只填 `metrics` 与 `status`，其余留给后续 spec。

## 一、账本 schema

新增 `backend/data/projects/{pid}/commits.jsonl`，每行一个 JSON，**追加写入永不修改**。

与 `journal.py` 的断点收据是两种东西：

| | journal.py 收据 | commits.jsonl 账本 |
|---|---|---|
| 语义 | 幂等缓存 | 历史 |
| 写入 | 覆盖（同index 去重） | 追加 |
| run_key 变化 | 全部作废 | 无关 |
| 用途 | 断点续写、不重复调 LLM | 跨章趋势、修订追溯 |

行结构：

```json
{
  "ch": 12,
  "stage": "polish",
  "ts": "2026-10-22T14:30:00",
  "status": "draft",
  "run_key": "a3f9c2e1",
  "metrics": {
    "chars": 4820,
    "burstiness": {"question_density": 7.2, "char_type_density": 0.41,
                   "comma_density": 62.0, "number_density": 3.1,
                   "time_anchor_density": 2.4, "sentence_cv": 0.53},
    "rhythm": {"段落数": 142, "长段数(>80字)": 5, "单句成段占比": 28.3,
               "最长连续单句段": 3, "动作收尾占比": 31.0, "极短段(≤12字)": 22},
    "verdict": {"p0": 0, "p1": 2, "ai_hits": 3, "banned_hits": 1}
  },
  "before": {"sha256": "…", "chars": 4901},
  "notes": "第2轮重写后达标"
}
```

**status 三态**：

| status | 含义 | 计入趋势 |
|---|---|---|
| `draft` | 生成完未确认 | 否 |
| `accepted` | 过门禁且作者定稿 | 是 |
| `revised` | 定稿后又改 | 是（取代同章前一条 accepted） |

只有 `accepted` 计入趋势统计——与 `journal.py:93` 的 `match()` 只认 completed 同理：半成品不能污染趋势。

状态变更用**新增 `revised` 行**而非原地修改，这样重放时能看出「这章被反复改了几次」。

## 二、落库时机

### 钩子 A：每个块门禁后

位置：`engine.py:516` 之后（`_apply_burstiness_guard` 已执行完）。

这是指标最完整的时刻——降级护栏已把「连续未改善降级为 P1」处理完，落库的 `verdict.p0` 是**降级后**的真实值，不是初判值。记录 `status="draft"`。

### 钩子 B：章定稿时

位置：`desk.py:1042` 的 `project_store.adopt` 附近。

把该章最后一个块的账本行status 从 `draft` 改成 `accepted`，实现为**追加一条 `accepted` 行**（而非原地改），使其可重放。

### 钩子 C：`record()` 被调用时 —— 本 spec 不做

`store.py:328` 的 `record()` 会清空 `finalized_at`，说明「定稿后又动了」，正是 `revised` 的触发时机。但 `record()` 拿不到 metrics（那是 engine 的局部变量），要传就得改函数签名。

**留到 spec 4（人工确认门）一起做**，届时签名改造是必然的。

### 失败策略

落库必须**静默失败**：包在 `try/except` 里，记 debug 日志，绝不让账本写失败阻断生成。照抄 `lexicon` 的做法（`engine.py:537`）。

## 三、趋势算法

单章指标无意义，因为阈值是绝对值，而退化是**变化率**。分三级：

### 一级 · 单章越界

复用现有 P0/P1 阈值，零新增计算，直接存 `verdict`。

### 二级 · 滑动窗口退化

取本章往前 N 章（N=5，可配）的同一指标，比对两个窗口均值：

```
recent   = 近 5 章均值
baseline = 前 5 章均值
rel = (recent - baseline) / max(|baseline|, ε)
```

用**相对变化率**而非绝对差，因为不同指标量纲差异极大（字种密度 0.41 vs 问号密度 7.2）。

| 指标 | 退化方向 | rel 阈值 |
|---|---|---|
| `question_density` | 下降 | `< -0.35` |
| `char_type_density` | 下降 | `< -0.15` |
| `number_density` | 下降 | `< -0.35` |
| `time_anchor_density` | 下降 | `< -0.35` |
| `长段数(>80字)` | 下降 | `< -0.40` |
| `动作收尾占比` | 下降 | `< -0.30` |
| `sentence_cv` + `极短段占比` | **联合** | 见下 |

**`sentence_cv` 必须联合判定。** `humanize.py:545` 注释明确写了「句长均匀度人机无差异（R=0.87）」，所以 CV 上升本身**不是 AI 信号**。仅当 CV 上升 **AND** 极短段占比同时上升时才报——这是「双信号互证」原则，避免把一个已被实证证伪的指标重新引入。

### 三级 · 硬阈值趋势

`rhythm.最长连续单句段 >= 6`（瀑布体）、`chars < 3000`（情节点密度不足）。这两项跨章累积才有意义。

## 四、注入任务书（闭环最后一环）

账本只是记录，**注入才是闭环**。`build_chapter_checklist()` 现六段结构（`ledger.py:567`），加第七段：

```
【趋势红线】（前三项均为跨章统计结论，不是单章判断）
· 问号密度已从 7.8 滑到 4.9/千字（-37%）：本章必须补内心反问或对白问句
· 长段数已从 5 降到 3（-40%）：本章至少留 3 段 >80 字的长段承担描写
· 数字密度连续 3 章下滑：本章补具体数字（房号/时间/价格）
```

**措辞设计**：用**叙事性记忆**而非禁令。照抄 `lexicon.py:274` 已有的手法（「上一章你把『冷风』用了 4 次」而非「禁止使用冷风」）——命令式禁令会压缩模型的选择空间。

**只注入 top 3**，按退化幅度排序。理由：`ledger.py:663` 的 8:2 段与任务书总长都有预算约束，注入 8 条会挤掉前三段。

**注入位置**：与现有⑤「怎么写更顺」同段末尾——它们都是「写的时候要避开什么」。

## 五、防误伤（三条硬约束）

这套东西最大的风险是**把正常波动当退化**，让模型去修正一个不存在的问题。这比不做更糟。

1. **样本不足不判定。** 前 10 章不产出趋势结论（需要 N=5 + baseline 5）。少于 10 章时趋势段整个不出现。
2. **只报单调退化，不报单章跳变。** 必须「近 5 章均值 < 前 5 章均值」，单章忽高忽低不报。否则模型会为迎合指标写出忽快忽慢的怪东西。
3. **注入的是「提醒」不是「P0」。** 趋势红线**不进 hard_gate**，只作为任务书文本进 prompt。硬门禁是「这章写坏了必须改」，趋势是「这本书在退化，你注意」——性质不同，混在一起会让门禁不可预测。

连续 3 章触发同一条 = 不是波动是真退化，第 4 章注入文案升级为「**本项已连续 3 章退化，本次必须处理**」。

## 六、测试策略

| 测试 | 验证什么 |
|---|---|
| stats 完整落盘 | metrics 字段与 SSE 推的一致 |
| 10 章合成数据 → 第 11 章任务书 | 趋势段出现，措辞含具体数字 |
| 前 10 章合成数据 → 任务书 | 趋势段**不出现**（约束 1） |
| 锯齿数据（升1降1循环） | **不报**（约束 2：非单调） |
| 单章 CV 升但极短段没升 | **不报**（双信号互证） |
| 账本写入失败（只读目录） | 生成**不中断**，debug 日志有记录 |
| `revised` 行重放 | 同一章多行，后 `accepted` 的生效 |
| 现有 39 个既有失败 | 数量与改动前一致（回归基线） |

## 七、本 spec 不做什么

- **不改任何阈值。** 现有 P0/P1 全部保留，本次只做记录与趋势。阈值调整需实证数据支撑，现在调是拍脑袋。
- **不做钩子 C。** `record()` 拿不到 metrics，留给 spec 4。
- **不重放重建。** 账本是追加式历史，趋势只往前读。「按账本重建真相文件」是 spec 3 的事。
- **不碰 `sentence_cv` 单项判定。** 只在联合条件里用它。
