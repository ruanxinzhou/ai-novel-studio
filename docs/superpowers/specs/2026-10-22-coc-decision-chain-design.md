# 副本跑团第三步 · 决策链分镜（把"扮演"改成"记录决策"）

## 零、这一步在做什么

作者对当前实现的判断：**跑团模拟实况不该是让大模型扮演 PL 和 KP 互相推演**。

要的是「在一个跑团背景下，不一样的几个故事」的可读形态：

```
什么样的几个 PL 怎么进入这个剧本剧情
  → 他们在什么时候做了什么动作
    → KP 判定，得到了什么结果（信息）
      → 导致剧情怎么样发展
        → PL 面对新的情况又做了什么
          → 得到了什么……
循环下去，一直到有一个故事的结局
```

**核心断言：这一层的产物是「决策链」，不是「对话体验」。**

---

## 一、当前实现错在哪

| 维度 | 当前实现 | 应该的形态 |
|---|---|---|
| KP 回合产出 | 300-400 字环境描写 + 氛围渲染 | 判定结果 + 信息增量 |
| PL 回合产出 | 第一人称心理描写 + 动作描写 | 动作声明：做了什么 / 为什么 / 想验证什么 |
| 骰子 | 模型用中文「想」出「投掷 侦查：63/100」，正则抠出来 | 真掷：确定性 RNG + COC 七级结果 |
| 核心价值 | 文字体验（但通稿层会重写一遍，等于写两遍） | 因果链可读 |
| 终止依据 | 靠模型自己说「故事收束了」 | 靠信息链闭合 |

**双重写作问题（慢的根因）**：描写写一遍 → 梗概再写一遍 → 通稿再写一遍。
同一件事三次生成，token 花在了两次会被丢掉的中间产物上。

---

## 二、三条已确认的设计决策

作者已确认：

1. **两个回合不合并** — KP 判定与 PL 决策保持两次独立调用。
   合并会让一个模型自己出题自己答，判定失去独立性。
2. **要真掷骰子** — 引入确定性 RNG，骰子由代码掷，不由模型编。
3. **不迁移旧数据** — 42 场旧跑团记录不兼容新格式。

---

## 三、真骰子引擎

### 3.1 为什么必须真掷

现在 `parse_dice_rolls` 从模型输出的中文里正则抠骰子。这有两个硬伤：

- **不可复现**：同一模组两次跑，骰子不同但无法重放，事后无法追查「为什么这场是这个结果」。
- **判定不可信**：模型倾向于让 PL 成功（戏剧性需要），实际成功率虚高。

真掷 = 代码掷 = 可复现 + 可审计 + 不受模型倾向影响。

### 3.2 COC 七级结果

标准 COC 判定规则，`1D100` 投出 `r`，技能值 `skill`：

| 结果 | 条件 |
|---|---|
| 大成功 critical | `r <= skill/5` |
| 极难成功 extreme | `r <= skill/2` |
| 困难成功 hard | `r <= skill` |
| 成功 success | `r <= skill*0.8 + 20` |
| 大失败 fumble | `r >= 96`（且不是大成功） |
| 极难失败 extreme_fail | `r >= 96` |
| 困难失败 hard_fail | `r >= skill*1.2 + 10` |
| 失败 failure | 其余 |

从高到低匹配，命中即停。

### 3.3 确定性 RNG

用 `random.Random(seed)`，seed 从 `field_no + session_index` 派生。
同一场重跑（同seed）→ 完全相同的骰子序列，便于复盘。

**随机性来源**：`_dice_roll(state, skill, bonus)`，把每次掷骰记进
`state.roll_log`，构成可回放的完整记录。

## 四、KP 拍：结构化裁决

### 4.1 输出格式

KP 不再写描写，输出一个 JSON 裁决块：

```json
{
  "scene": "井口（场景定位一句话，供通稿层展开）",
  "check": {
    "skill": "侦查",
    "difficulty": "困难",
    "success_effect": "井壁有三道新鲜刮痕，三天内有人下去过",
    "failure_effect": "井壁只有陈年苔痕，什么也查不出"
  },
  "information_gained": "井下三天内有人下去过",
  "world_state_change": "井下的东西知道有人来了",
  "known_now": ["井壁有新鲜刮痕", "井里有回应声"],
  "unknown_now": ["谁下去的", "井里的是什么"],
  "next_pressure": "井里的回应叫出了同伴的名字",
  "story_phase": "展开中"
}
```

`check` 的**判定结果由代码掷骰决定**，KP 只负责提供成功/失败两套
`effect` 文本——代码掷出 `success` 就取 `success_effect`，掷出 `failure`
就取 `failure_effect`。KP 不能决定成败。

### 4.2 为什么保留 `scene`

纯结构化会丢掉全部画面。保留一句场景定位，让通稿层有锚点可用，
但不在这一层展开——展开是通稿的活。

---

## 五、PL 拍：动作声明

### 5.1 输出格式

```json
{
  "action": "喊话，不下去",
  "motivation": "怕死，但井里的回应叫出了同伴的名字",
  "hypothesis": "井下有人，且认识我们",
  "cost": "暴露了自己的存在"
}
```

四个字段对应作者的四个要求：**做什么动作 / 为什么 / 想验证什么 / 付出了什么**。

### 5.2 PL 不再写心理描写

心理活动在通稿层由 `motivation` + `hypothesis` 展开。
这一层只留决策，展开留给下一层。

## 六、产物：分镜表

跑完后 `state.storyboard` 是这样一张表：

| 拍 | PL 动作 | 判定 | 信息增量 | 剧情变化 | 遗留压力 |
|---|---|---|---|---|---|
| 1 | 撬开井盖 | 侦查 63/50 困难成功 | 井壁有三天内的新刮痕 | 井下物知道有人来了 | 井里叫出了同伴名字 |
| 2 | 喊话不下去 | 意志 44/50 失败 | 回应声更近了 | 同伴被单独叫走 | 剩下的人在井边 |

**这张表就是作者要的「几个不一样的故事」。** 三场跑完 = 三条不同的决策路径。

落库到 `state.storyboard`，字段独立于 `final_summary` / `full_narrative`。

---

## 七、终止判定

新的终止依据不再是「模型说要收束」，而是**信息链闭合**：

| reason | 条件 |
|---|---|
| `chain_closed` | KP 报 `story_phase=已收束` 且 `known_now` 覆盖核心秘密 |
| `hard_cap` | 撞 beat 预算 |
| `dead` / `insane` | 全员倒下 / SAN 归零 |
| `no_progress` | 连续 N 拍 `information_gained` 为空（原地打转） |

`no_progress` 是新增的：PL 反复试探已确认的事，是决策链模拟最常见的
空转形态，必须能自动掐断。

---

## 八、顺带解决慢的问题

| 措施 | 效果 |
|---|---|
| KP 输出从 300-400 字压到 ~120 字 | 单拍延迟下降 |
| PL 输出从 300-400 字压到 ~80 字 | 同上 |
| 跑团层跳过硬门禁重试 | 最坏 3× 调用 → 1× |
| 上下文只带决策链不带描写 | input token 大幅下降 |

**预期总耗时降到原来的 1/3 以下**，且产物比原来更有用。

---

## 九、不做

- 不合并 KP / PL 回合（作者已确认）
- 不迁移旧跑团记录（作者已确认）
- 不做数值战斗系统（这不是战斗模拟，是决策链记录）
- 不让 PL 拍读取 KP 描写文本（只读判定结果，独立性）
