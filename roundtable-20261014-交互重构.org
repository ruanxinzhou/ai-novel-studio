* 开场：定义

**主持**：两种交互模式——
- 模式A（向导式/当前工具）：分阶段填必填门控，AI检查通过才推进，像填签证表。
- 模式B（策展式/用户要的）：每步AI基于上游锁定内容直接产出N个完整可读候选，人挑一个改/润色/锁定，下一步AI基于锁定的继续生成。像逛画廊挑画买回家改。

**【刘慈欣】【陈述】**：本质差别是"谁握着笔"。模式A笔在AI手里，你是它的雇员；模式B笔在你手里，它是你的矿场。笔不在自己手里那一刻作品就死了。我站B。
**简言之**：作者必须是独裁者，AI只配当素材矿。

**【罗宾·斯隆】【补充】**：模式A假设你知道自己要什么只是需要结构；模式B假设你不知道自己要什么，但你看见不喜欢的东西立刻就知道。写作真相是后者。
**简言之**：人不知道自己要什么，但一秒能认出自己不要什么——这是策展式成立的认知学前提。

**【南派三叔】【陈述】**：卡壳时编辑追着问"情绪落点是什么"——我就是因为不知道才卡！你给我写三个版本，我看一眼就知道哪个对，改二十分钟就写完了。"挑"比"想"快十倍。
**简言之**：卡壳的人答不出"你要什么"，但三秒能挑出"哪个是我的"。

**【罗伯特·麦基】【质疑】**：人没给输入时AI生成的5个是基于随机种子+克苏鲁套路的组合爆炸——这5个有什么价值？最后出来的是AI审美平均值上的平庸小说。门控虽然烦，但它逼你先想清楚再让AI动。
**简言之**：没先想清楚"要什么"就生成，生成的是噪音。

**【原研哉】【综合】**：麦基担忧对但药方错。无印良品做椅子不会先让设计师填"坐高/材质/承重"表——而是让五个设计师各拿一把1:5纸糊模型摆桌上看、摸、坐，然后说"第三把曲线对但颜色不对，把第一把颜色移过来"。人是在看见具体形状之后才想清楚的，不是之前。
**简言之**：人在看见具体形状之后才想清楚，不是之前——这是"先给方案再让人选"比"先问清楚再让人填"更符合认知的原因。

* 第二轮：生成协议 + 漏斗粒度 + 数据模型

用户补充："这个过程是持续拆分的——副本核→骨架→章节→章细纲→日更草稿→润色→定稿，每一步锁定的内容要和书与定稿/今日章台关联同步。"

**【刘慈欣】【陈述】**：我写三体最早只有"叶文洁按下按钮"一个画面。围着它写三四个开头，挑最"冷"那个继续。每次我挑的不是"最好"的，是"最让我不舒服"的——让我舒服的都是套路。N个必须在同一个"锁"上变化，从上游线头里长出来，不是随机抽。N=3够，每个是成品级可读文字，不是参数表。
**简言之**：每阶段3个，必须从上游锁定的线头里长出来（不是随机），每个是成品级可读文字。

**【罗宾·斯隆】【补充】**：N个版本必须在某个关键维度走三个极端。差异轴必须明确，否则挑就是假挑。挑完是对话编辑，不是重新生成。
**简言之**：3版本在关键轴上走三个极端；挑中后是对话编辑。

**【南派三叔】【陈述】**：漏斗越往下N变化——副本核300字/骨架卡200-500字/章节表一行50字/章细纲5-9场每场1-2句/**日更草稿是正文，不能再3版**（太长看不完）。日更正确做法：AI基于细纲直接出一版完整草稿，读到哪段不对就地改。N从3降到1，是"编辑模式"不是"挑选模式"。
**简言之**：漏斗越往下N从3降到1，日更草稿只出一版就地改。

**【罗伯特·麦基】【反驳】**：用户说"敲定内容要关联书与定稿/章台"——这意味着当前"session.outputs临时缓冲区→最后写正式存储"的模型是错的。必须"对话就是在编辑正式卡片"，锁一个字写一个字。
**简言之**：对话改的每一笔必须直接写入正式存储，废临时缓冲区。

**【原研哉】【综合】**：回转寿司三层模型——
1. 传送带永远有3盘（候选区并排），看不上点"再换一拨"
2. 选中进入编辑态对话改，改到满意点"就定这版"
3. 每盘都是可读成品文字不是表单，字段从文字后解析

* 第三轮：世界状态热板

用户补充："实体库很重要——每一步AI要主动判断/让我挑选新出现的角色地点道具情节线伏笔，以及他们状态发生了什么改变；状态是链式的、互相关联推进。"

**【刘慈欣】【陈述】**：叫"世界状态表"(World State Sheet)，是TRPG角色卡延伸。每个实体是带三层状态的卡：基础值/当前值/变动原因（谁导致/何时/哪章）。每次锁定文本后AI扫描变化弹checklist让你勾。
**简言之**：实体是带三层状态（基础/当前/变动原因+章节）的TRPG卡；每次锁定后AI析出变化checklist。

**【罗宾·斯通】【补充】**：涟漪传播(Ripple Propagation)——AI不只是列"直接变了什么"，应沿关联边提示"这个变化可能波及哪些相关实体"让作者决策。技术上是图：节点是实体，边是关联。
**简言之**：状态变化沿关联边提示可能波及的实体，让作者决策而不是AI决策。

**【南派三叔】【陈述】**：日更侧边栏常驻"本章涉及实体/状态"面板——打开章就看到唐迟SAN、陆听白怀疑度、朱砂纸温度、未回收伏笔。召唤AI时上下文自动注入这张表。
**简言之**：日更侧边栏常驻本章状态面板，AI召唤时自动注入。

**【罗伯特·麦基】【修正】**：我修正立场。状态表本身就是最强约束——代替了门控。硬性规则：每次生成prompt必须程序强制注入状态表快照，不靠AI"记得"。这是防套路、防OOC、防吃设定的根本。
**简言之**：状态表是天然强约束，替代门控；每次生成强制注入快照。

**【原研哉】【综合】**：升级为四层模型——
```
┌─ 第四层·状态热板（全程常驻，每次锁定弹checklist） ─┐
│ □新实体 □状态变化 □新伏笔 □伏笔回收 □涟漪预警     │
├───────────────────────────────────────────────────┤
│ 第三层·候选区（3盘并排+换一拨，带差异轴）           │
├───────────────────────────────────────────────────┤
│ 第二层·编辑态（对话改原文，不是字段表）             │
├───────────────────────────────────────────────────┤
│ 第一层·正式存储（即时写入）                         │
└───────────────────────────────────────────────────┘
```

* 开放问题

1. 差异轴由谁定：固定几个轴 vs AI根据上一阶段产物自动选轴（M2先固定，后续自动）
2. 编辑态落选版本命运：丢弃 vs 保留为备选（倾向保留最近3版+锁定版）
3. state_diff触发时机：每段/每轮/锁定时（倾向锁定时抽，对话中可手动触发）
4. 涟漪预警几步：1步 vs 2步（倾向1步+AI判断是否提示2步）
5. D1副本怎么接入：继续旧流程+手动状态板 vs 重来（倾向前者，D2才正式启用）
6. COC模拟器输出：直接展示 vs 当AI素材（倾向当素材不直接展示）
7. 审稿7项：必过 vs 可强行锁稿（倾向默认必过加强行锁稿留"未过审"标记）
